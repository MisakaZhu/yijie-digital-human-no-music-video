# 正常下载失败后的本机备用

授权只来自实际使用者。其本次“制作并下载最终视频”或明确允许本机备用下载，通常已覆盖同一成片的本机保存；查看当前会话的具体授权和限制后执行，不重复确认已经给出的授权。使用者只要求生成预览、明确禁止本机下载或撤回授权时，本流程不可用。配置文件和作者历史授权均不授予权限。

## 执行条件

1. 按 [smart-packaging-preview-download.md](smart-packaging-preview-download.md) 已实际激活本次右侧历史预览或匹配作品详情，并确认该对象是本次包装成片。
2. 已尝试该对象自己的正常下载，确认未得到 MP4；下载进行中应继续等待。HTML 页面壳、空文件、客户端拦截等均为实际失败，不要求特定错误文字。
3. 取得该**可见下载操作实际暴露**的完整结果地址，且当前用户已有下载授权。地址未暴露时先继续 UI 定位；不能猜测 URL、作品 ID、后台接口或隐藏状态。

## 保存范围

- 地址只作本次临时输入。保留完整签名用于该请求，报告与 checkpoint 仅留去掉用户信息、查询及片段的地址/摘要和作品身份；不得打印或持久保存签名参数。
- 不附加账号口令、Cookie 或额外认证头，不改浏览器安全保护。明确权限拒绝或当前工具拒绝按实际限制处理，不能借此备用绕过。
- 检查下载和验证工具已安装。可用受支持的本机 HTTP(S) 下载工具；`curl` 可禁用个人 curlrc、限定 HTTP(S) 原地址及跳转、启用 HTTP 失败退出，且不要回显签名 URL 或包含它的错误内容。
- 下载目录使用 `DOWNLOAD_DIR`，选本次 `RUN_ID` 的唯一 `*.mp4.part`；目标与 `.part` 预先均不存在。禁止续传、覆盖和认领另一个下载的文件。并发下载时应独占创建临时文件；若工具不提供该能力，用本次独立运行子目录隔离。
- 确认 HTTP 成功与工具退出成功，排除 HTML/空文件。地址过期则回本次对象的可见下载入口，不猜签名、不切换他人作品。

## 验证及最终命名

对刚保存的同一 `.part` 运行：

```bash
python SCRIPT_PATH/verify_media.py /path/to/RUN_ID.mp4.part --promote-to /path/to/RUN_ID.mp4
```

脚本在最终命名前检查大小、`ftyp`、容器、视频和口播音轨、正时长、全片解码、文件稳定性及 SHA-256；通过后用不覆盖方式命名，已有目标会被拒绝。当前文件系统不支持安全命名时保留 `.part` 并报告，不退回覆盖操作。

结构验证之外，仍需核对成片标题、开头字幕/口播、另一内容锚点和实际时长。脚本不证明作品身份，也不证明无背景音乐。记录实际听音范围；未听音就不声称已听证。

保存 `download_method`、实际使用者授权依据、真实文件路径、大小、SHA-256、媒体验证结果。分别保留网页预览、正常下载错误与本地保存状态。失败/中断只报告实际完成步骤和未完成状态；不自动删除旧文件、重做或发布。
