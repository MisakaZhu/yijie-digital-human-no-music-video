# 剪辑高手：定位本次成片与下载

用于标准流程第 10–13 步，以及中断后恢复成片核验。网页交互使用工具公开支持的 UI 能力，不调用后台接口或读取隐藏应用状态。正常下载失败后按 [authorized-local-download.md](authorized-local-download.md) 核对使用者本次或既有下载授权，再执行本机备用下载；不存在作者授权继承，也不限定某个错误文字。

## 先激活，再判断（不能跳过）

**顺序：确认提交状态 → 找本次右侧历史卡片 → 点击其视频缩略图 → 再核对中央播放 → 下载。**

- 到达结果页、进度消失或恢复任务后，先检查本次结果有没有实际激活。没点过本次右侧卡片时，中央 `无法播放媒体` / 黑屏 / `0:00` 默认记为 **结果未激活**，下一步必须是定位并点击，不能据此停下来请用户发截图或确认备用下载。
- 查看截图、读到 `下载/重新生成`、选中过模板或点击左侧源视频，都不等于点过本次右侧结果预览。
- 右侧没有匹配记录时，先查本次保存位置的作品库成片（第 3 节补充路径）；不盲点第一条，不反复检查同一组旧记录，不把补提作为默认下一步。
- 下载前必须记录实际的 `result_origin`、所选记录依据和 `result_preview_clicked_at`。字段填写必须对应实际工具动作；不能为通过流程补写一个不存在的点击。重新打开或恢复页面后，再核对选中对象，必要时再次激活。
- 自己尚未完成这些动作时，不输出“等页面可以播放再继续”“请指出哪条是本次结果”“出现 ERR_BLOCKED_BY_CLIENT 后发截图”作为处理结论。

## 1. 保留本次任务依据

沿用流程开始时按 [task-isolation.md](task-isolation.md) 建立的 **本次独立 `CHECKPOINT_PATH`**（`.yijie-runs/<run_id>/task-checkpoint.json`）。不要重新建立根目录同名 checkpoint，也不要读取其他任务或最近修改的记录。先核对 `run_id`、当前来源及可用的任务 ID，再补充包装字段；字段只填实际观察到的值，未显示的值用 `null`：

- `browser_id`、`tab_id`、`page_url`；标签组名称可作辅助，不代替内容核对。
- `title`、`narration_opening`（开头一句）、`narration_anchor`（另一句有辨识度的口播）。
- `topics`：按主 skill 核验的恰好 5 个不重复话题，若配置 `REQUIRED_TOPIC`，它出现一次；其余话题与本条内容相关；交付时沿用这 5 个话题。
- `source_asset`、`source_transfer`、`source_file`、`source_duration_seconds`；云端作品库转入时 `source_file = null`，保留已核对的作品 ID/URL/内容证据。时长取实际源片 UI 或受支持媒体信息，不从字数估算，不为取得精确秒数强制下载原片。
- `verified_settings`、`pre_submit_screenshot`、`submitted_at`（带时区）。
- `submission_attempted_at`、`submission_acknowledged_at`、`submission_evidence`、`processing_status`：点击、受理/处理中与成片确认分开；页面显示时间不能充当 `job_id`。
- `job_id`、`selected_record_time`、`result_url`、`result_duration_seconds`、`completion_screenshot`。
- `result_origin`（`right_history` / `work_library`）、`result_preview_clicked_at`、`result_identity_evidence`、`history_lookup_status`、`work_library_lookup_status`。记录实际点击和对应关系，未做为 `null` / `not_checked`。
- `generation_status`、`preview_status`、`download_status`、`download_started_at`、`local_file`、`download_error`。
- 备用下载时另记 `download_method`、`download_authorization`、`local_validation_status`、实际大小、`sha256`、媒体信息和解码结果。含签名/令牌的 URL 只作当前下载的临时输入；持久记录仅留脱敏地址和作品归属，不保存完整签名参数。

进度变化后更新对应字段。选择历史记录可能让左侧编辑器切换到旧配置；编辑器重置不推翻提交前截图，不能据此重新上传或重做。不要保存凭证、Cookie 或其他历史任务内容。

## 2. 识别四种画面

| 页面区域 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 左侧上传视频播放器 | 当前编辑器载入的源片 | 包装已完成或成片已下载 |
| 左侧模板卡片/更多弹窗 | 蓝框/激活态对应当前模板 | 历史成片使用了哪个模板 |
| 右侧历史缩略图 | 存在一条候选记录 | 它属于本次任务，或主播放器已加载它 |
| 选中历史后中间主播放器 | 当前载入的输出内容与播放状态 | 未核对前不能认定是本次成片 |

同一数字人、衣服、窗边背景会在多条视频复用，不作为内容身份证据。视频文件名也可能继承旧任务名称；名称异常需要核对视频内容，不能直接判定源片错误。

## 3. 定位、选择、播放

1. **找回本次工作标签页。** 按 `task-isolation.md` 核对本次 checkpoint，再连接它记录的浏览器和标签 ID。不能因网址/标题相同或他人截图就打开并接管其他标签；遇到其他会话占用立即尊重该归属。确实关闭时，在原浏览器创建本次替代标签并记录新绑定，从已保存的提交信息找回结果，不重新提交。句柄有效时不另开“核验页”。
2. **扫描历史候选。** 从本次标题、内容和提交时间找记录，首条没有优先真实性。历史图片在可访问性树中可能只有“未加标签的图片”，需看新截图；滚动右侧历史面板，保留已查看候选的简短排除理由，避免反复点击同一旧项。点击前确认坐标属于最新截图，不沿用旧滚动位置或旧节点编号。查看本次时间窗口及相邻滚动范围；列表一直只显示早于本次提交的旧片/无关片时即转下面作品库路径，不遍历全库旧记录，也不要求用户替模型定位。
3. **选中才加载。** 必须实际点击候选历史卡片的视频/缩略图区域，确认选中边框或指示标记，再等待主播放器更新，记录 `result_origin = right_history` 和 `result_preview_clicked_at`。边框只证明选中了该卡片。截图可能比文字状态晚更新；发现两者不一致时再读一次最新画面，不把上一帧当作当前结果。未做这一步之前禁止把中央播放器状态当成本次播放结论。
4. **核对内容身份。** 检查输出画面标题与 `title` 一致，播放后开头字幕/口播与 `narration_opening` 一致；若标题关闭或被模板裁切，检查两个有辨识度的口播片段。可见的任务 ID/记录时间应与提交记录相符，时长应与源片相近。缺少某个字段时注明未知；内容和来源足够明确时，不因缺少任务 ID 单独阻塞。若多条记录同名同内容，进一步核对任务时间/ID/结果 URL，无法区分则保持未确认。
5. **处理时间。** 保留页面原始时间，比较时统一时区；带 `Z` 的时间是 UTC。来源不明的页面时间不能替代任务创建时间。`1:00` 是播放器的粗粒度显示，不能据此否定媒体探测得到的约 60.9 秒。若时长明显不同，核对片头片尾或内容，不强行认作同一条。
6. **验证可播放。** 在选中的输出播放器点击播放，观察几秒内画面和时间进度推进，读取至少开头一句，随后暂停。播放按钮存在、海报显示、进度静止或显示下载按钮，都不足以证明播放正常。没有听音能力时只记录画面/字幕/进度检查，不声称听过音轨或已听证无音乐。
7. **确认成片。** 记录选中卡片、主播放器标题/字幕、时长和时间的截图；若允许的页面能力暴露结果 URL，保留其关联，签名地址只保留在本次临时输入中，持久记录脱敏。不要从历史封面地址、数组顺序、源片 URL 或其他标签的播放器推测结果 URL。

### 右侧缺少本次记录：从作品库找回成片

1. 保留本次提交和配置记录，在 **本次标签** 打开可见的 `作品库`，进入实际保存位置（通常 `我的/作品库`），筛选 `视频`。这个入口用于查找已有本次输出，已在标准流程授权范围内。
2. 找标记为 `智能包装合成结果` / `来自：智能包装原子能力` 的记录；用本次生成时间窗口、名称/ID、标题、时长和内容缩小范围。列表中的 `来自：数字人视频` 是原片，不得作为最终包装成片交付。右侧历史不更新并不证明作品库没有新结果。
3. 打开候选作品自己的详情/预览，记录 `result_origin = work_library`、记录身份、创建时间和 `result_preview_clicked_at`。不要把该包装结果重新选入左侧源片编辑器。
4. 核对它与本次运行的关联。时间相近只是筛选依据；同名同人物仍需内容/可见产物 ID 等佐证。有可靠关联但网页播放器不加载时，可以点该对象自己的正常下载，用本地画面、字幕/口播和媒体信息完成内容核验，保留网页预览未确认状态。
5. 库中已有本次候选时先核对、下载；不能一边发现对应时间的现有包装结果，一边自动补提生成。候选被排除后才继续其他有依据的记录。

内容明显不一致的候选应排除。只有标签绑定、右侧历史范围、本次作品库位置/筛选及可见详情均已检查，仍缺足够证据时，才报告“尚未定位本次结果”，列出具体缺项并保留已受理任务；不推断它不存在或必须付费重做。暂停/结束当前轮前，按工具文档保留本次工作标签；不使用另一个任务的标签代替。

## 4. 对状态作出对应判断

| 观察到的情况 | 判断与下一步 |
| --- | --- |
| 只有点击动作/按钮转圈，没有受理证据 | 记提交尝试；读本次校验/错误与结果记录，不宣称成功，也不盲目连点 |
| 本次任务仍显示进度或制作中 | 继续等待，尤其不要在 99% 刷新/重提 |
| 进度消失，出现时间与下载按钮 | 转到结果定位和实际激活，不能仅凭这一行认定本次成片已确认 |
| 中央播放器黑屏、0:00、无法播放，且还没点本次右侧预览 | 必做下一步：定位并点本次右侧卡片；不能停下索要截图/授权 |
| 已点匹配卡片，主播放器仍黑屏或禁用 | 有限重选并等待；记录网页加载问题，产物归属明确时继续正常下载核验 |
| 点开后标题/口播是其他主题 | 排除这个候选，继续定位；不推断本次上传错了 |
| 右侧范围已查全是旧片/无关片 | 查本次作品库的包装成片详情；不把重提当默认恢复 |
| 已确认内容，但播放器仍缓冲/失败 | 记为预览加载问题；正常 UI 下载入口可用时可保存同一结果后本地核验，不能把播放失败直接当生成失败 |
| 匹配本次任务的记录明确显示生成失败 | 保存该记录与错误，报告确证失败；额外付费重做按已有授权范围处理 |
| 主播放器已确认本次内容，但下载请求报错 | 保持生成完成，单独记录下载错误 |
| 用户指出正确记录或提供新截图 | 以新证据重新定位并核对；不重复已经被用户纠正的旧记录搜索 |

加载恢复采用有限重试：正常短时等待后最多重选同一卡片一次，再观察约 5–10 秒；若仍无变化，保存状态并转入对应分支。明确仍在生成的任务按生成进度等待，不能套用播放器加载超时判失败。用户已指明目标时先处理该线索。不得仅因加载失败、选错历史或下载失败点击 `重新生成` / `进行智能剪辑`。

## 5. 下载与本地文件对应

1. 下载前检查已有本次历史卡片/作品详情的实际激活动作和 `result_preview_clicked_at`；没有就先激活，不能直接点击尚未载入结果页的下载。保存记录身份和核验依据，记录开始时间及已有同名文件，点击该对象的 `下载` 一次。可命名时带本次 `run_id` 或使用独立运行子目录；随机文件名按来源关联。
2. 紧接着读取当前页面/标签与浏览器下载状态（在工具支持范围内），区分：
   - **正常下载或保存框：** 完成命名/保存并等待结束，实际文件可能使用平台随机名。
   - **普通媒体播放页：** 只是打开了视频；若工具支持，可用该页面可见的正常保存/下载控件完成保存，不宣称已经下载。
   - **明确客户端拦截：** 记录本次记录身份、错误文字如 `ERR_BLOCKED_BY_CLIENT`、标签、时间及真实暴露的地址（签名参数不写入报告）。这个错误不指认具体组件或文件损坏。地址和本次归属明确时按 [authorized-local-download.md](authorized-local-download.md) 核对实际授权后备用下载；确认使用者已有明确下载授权时无需重复询问。
   - **HTML 页面壳、空文件或正常下载未得到 MP4：** 先核对是否实际激活了本次对象；没有就回到第 3 节点击。已经激活但中心下载仍保存网页时，改查匹配作品库详情的正常下载入口。真实成片 URL 暴露后按已有下载授权使用备用方式，不等待 `ERR_BLOCKED_BY_CLIENT`。HTML 页面的 URL 不能充当 MP4 地址。
   - **其他失败：** 记录真实提示。网络/下载失败且本次真实成片地址已取得时按已有下载授权可备用；明确登录、访问权限或工具执行拒绝仍按实际限制处理，不能借备用路径绕过。不把所有失败统一写成文件不存在。
3. 若下载点击带离了工作台，记录暴露的结果地址后可后退一次回到原标签。这是恢复下载上下文，不是重新提交。返回后编辑器可能重置，按 checkpoint 重新选择同一历史结果，核对内容；不据此重配或生成。
4. 检查本地实际文件非空、大小稳定、下载完成，排除 `.crdownload` 等临时文件。文件名/修改时间只是候选依据：应有该次浏览器下载来源/已核验结果 URL 与文件的对应，辅以时长、分辨率及内容抽查；缺少下载来源时尤其要比对画面和字幕/口播。若可用，用媒体探测工具读取时长、视频与音频流。仅“有 AAC 音轨”不能证明无背景音乐。
5. 用户已经下载并给出路径时，直接核对其文件。正确成片存在后，结束下载恢复；不要再次触发下载或生成。重命名若有需要，应在识别完成后进行，并保留原件/避免覆盖。
6. 分别报告已确认的生成、播放和保存状态，最终路径用真实文件名；无法听音、未抽查完整内容等边界只按实际情况说明。
