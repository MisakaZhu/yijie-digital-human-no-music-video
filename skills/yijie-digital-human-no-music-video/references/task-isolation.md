# 多任务：每次视频运行独立归属

开始网页操作前读取。适用于多个 Codex 任务共用浏览器、账号或工作目录的情况；单任务也按同一规则执行。

## 1. 先建立本次运行记录

- 每个新视频生成一个完整随机 UUID 作为 `run_id`。同一来源链接被重复制作也要分开；续做才沿用原 ID。
- 在配置解析后的 `RUN_ROOT/<run_id>/` 创建运行目录，其中维护 `task-checkpoint.json`，截图、文案和临时文件也放在该目录。默认 `RUN_ROOT` 为工作目录的 `.yijie-runs`；目录创建必须不覆盖已有目录。
- 可用 PowerShell 的 `[guid]::NewGuid().ToString('N')` 生成 ID；用 `New-Item -ItemType Directory -ErrorAction Stop` 创建新的运行目录，不用固定日期或标题代替唯一 ID。
- 将 **绝对 `CHECKPOINT_PATH`** 记在当前对话工作记录中。恢复时读取这个确切路径，先核对归属；不要在工作目录扫描后采用“最近修改”的 checkpoint。
- 已存在的根目录 `smart-packaging-checkpoint.json`、日期相同的 MP4 或其他任务的运行目录均不自动属于本次。旧任务迁移时，只从本对话明确记录的来源、操作和文件重建独立记录，保留旧文件；缺失证据不靠他人的记录补齐。

从一开始保留这些字段，未知值填 `null`：

| 字段 | 来源与作用 |
| --- | --- |
| `run_id`, `created_at`, `checkpoint_path` | 本次生成的 UUID、带时区时间和绝对路径 |
| `owner_thread_id` | 环境实际提供的当前任务 ID；不可取得时为 `null`，不得填进程号或编造 ID |
| `source_url` 或 `input_copy_sha256` | 用户原始来源；直接文案可对 UTF-8 原文计算摘要，另留开头/结尾便于核对 |
| `phase`, `accepted_copy`, `title`, `topics` | 本次进度、已接受口播、正文标题和恰好 5 个不重复话题（配置了 `REQUIRED_TOPIC` 时包含一次该话题） |
| `browser_id`, `tab_id`, `tab_origin`, `page_url` | 工具实际返回的身份，及“本次创建”或用户明确交接的依据 |
| `source_asset`, `source_transfer`, `source_file` | 本次数字人口播原片及转入方式，云端选取时本地路径为 `null` |
| `submitted_at`, `job_id`, `result_url`, `local_file` | 本次包装提交和成片，不能与原片身份混用 |

写回前核对 `run_id`、来源与本对话一致；有可用 `owner_thread_id` 时也必须一致。不同记录不能合并。不要把凭证、Cookie、浏览器完整清单或其他作品的正文保存进 checkpoint。

## 2. 标签页归属先于页面内容

1. **新运行创建独立标签。** 使用当前已登录 Chrome 的浏览器绑定，新建工作台标签；会话/分组名带本次短 ID，如 `🎬 一姐 a1b2c3d4`。立即保存工具返回的浏览器 ID 和标签 ID。组名只便于辨认，不提供权限或归属证明。
2. **续做只回连已绑定标签。** `getTab` 需要浏览器参数时显式使用已记录的 `browser_id`；不要遗漏后改试多个浏览器。新用户消息、页面慢或一次工具报错都不自动推翻绑定。
3. **库存列表只用于定位句柄。** 如需枚举，只看定位所需的 ID/URL 元数据；不要逐个打开同网址标签、获取他人正文或截图。相同网址、标题、头像、当前聚焦、最新标签、其他任务截图均不能证明归属。
4. **尊重占用。** 工具报告标签由其他会话持有时，不抢占、不换浏览器重试、不关闭或刷新它，也不把它的内容写进自己的 checkpoint。继续能独立完成的文案或文件工作。
5. **句柄失效。** 先在原浏览器的清单确认已记录 ID 是否仍存在，避免句柄误用。确实关闭时才新建本次替代标签，记录旧/新 ID；从本次 checkpoint 和共享作品库/历史中找回已提交作品。不能把找回标签变成重新付费生成，也不能接管现存同网址标签。
6. **用户明确交接现有标签。** 按用户给出的具体标签定位，确认工具允许使用且内容匹配当前来源后绑定。用户贴出界面示意或其他任务截图不等于交接控制权。

不要使用全局当前页、全局快捷键或公共剪贴板作为任务路由。优先用绑定标签的输入框填写和文件选择器。只有工具能确认弹窗属于本次标签时才操作文件框；不能确认时保留状态，不向不明弹窗输入路径。

## 3. 等待、写入与恢复

- 每次等待、重连、用户操作之后，读取绑定标签的最新状态；不复用之前的坐标、节点编号或默认选项。
- 提取前核对本次来源链接；改写前核对本次提取稿；音频生成前核对已接受口播；数字人生成前核对本次音频；智能包装提交前核对原片、标题、模板和无音乐设置。浏览器标签正确不代表页面内容一定正确。
- 页面内容突然改变、载入另一稿、选中另一原片时，暂停当前写入，保留本次记录，核对本次阶段和实际页面。不要反复覆盖“修复”，不要刷新他人标签，不要自动恢复并再次提交。
- 账号的作品库与历史记录可以共享，这是正常现象。其他作品出现不等于当前草稿被串改；始终按来源和内容匹配本次作品，不能用“第一条/最新一条”识别。
- **只有观察到编辑状态相互覆盖时**才把相关编辑/提交阶段改为轮流操作；先保留本次草稿并等待冲突解除，仍无法继续时一次说明具体冲突。独立标签和目录不能保证网站服务器草稿隔离，不要宣称已实现浏览器或账号级强隔离。
- 本次提交已成功就记录状态并等待/找回结果。编辑器清空、模板窗口丢失、另条历史被选中，都不是再次生成的依据。
- 中断等用户输入时，如工具提供 `markHandoff`，保留本次工作标签；可交付页面按 `markDeliverable` 保留。只按当前工具文档使用，不能为防丢失接管别的任务标签。

## 4. 文件也按运行归属

- 原片默认留在作品库。确需本地传递时，名称带完整 `run_id`，或存入独立运行子目录；禁止复用只有日期的中转文件名。
- 平台随机文件名也可以使用，但必须记录它与本次下载来源、内容和时间的对应，不能选下载文件夹“最新 MP4”。重名时选新路径，保留现有文件。
- 最终成片放使用者配置的 `DOWNLOAD_DIR`，记真实路径。多任务同时下载时，时间只作辅助证据，不能代替下载来源和内容匹配。
- 更新 skill 不代表已经运行的任务会重新读取指令。不要代替用户改写或接管那些任务的页面、旧 checkpoint 或成片。
